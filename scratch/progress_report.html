1. Executive Summary & Technology Overview

BrishtiLibrary (বৃষ্টি লাইব্রেরি) is a comprehensive academic e-commerce bookstore and stationery shop developed for the CSE214 Algorithm Lab. The core academic requirement dictates that the entire backend server must be implemented purely in C (C99), utilizing SQLite via its official C API (sqlite3.h), native Windows Sockets (winsock2.h), and cJSON, accompanied by a clean, responsive HTML5/CSS3/Vanilla JavaScript frontend.

All backend services—including session token management, atomic checkout transactions with row-level stock decrements, image payload binary signature validation, 5,000-round salted password stretching (FIPS 180-2 SHA-256), non-blocking online database backups via the SQLite Online Backup API (sqlite3_backup_init), and algorithm visualizer microsecond benchmarks—are built natively in C without external runtime engines.

3. Existing Issues Diagnosed & Solutions Applied

  • Issue 1: Overwrite Protection in Online Database Backups:
    Root Cause: Calling sqlite3_backup_init where the destination path refers to the active database file (either via identical string, different case, or relative paths like ./database/brishti.db) causes database deadlocks, error code SQLITE_BUSY, or potential corruption.
    Solution: Resolved the active database path and the target backup path into canonical absolute paths using Win32 GetFullPathNameA and performed a case-insensitive check with lstrcmpiA. If the paths match, the function aborts immediately returning SQLITE_MISUSE before opening any destination database connection.
  • Issue 2: Backup Destination Directory Auto-Creation:
    Root Cause: sqlite3_open fails with "unable to open database file" if the parent directory database/backups does not yet exist on disk.
    Solution: Added automatic parent directory creation inside db_backup_to_file and server_start, ensuring robust standalone and server execution.
  • Issue 3: Missing Image Persistence in SQLite Products Table:
    Root Cause: While the upload endpoint saved binary files to frontend/uploads/, the SQL query in db_admin_create_product_json and db_admin_update_product_json omitted the image_url column from the INSERT and UPDATE statements.
    Solution: Added image_url parameter extraction from JSON payloads, updated parameterized SQL queries in database.c, bound text buffers, and included image_url in product catalog queries.
  • Issue 4: Admin Setup JSON Field Discrepancy:
    Root Cause: The backend endpoint in server.c strictly queried for "email" in the request JSON, while the admin UI and testing scripts submitted "username".
    Solution: Updated server.c to flexibly accept either "username" or "email" across /api/admin/setup and /api/admin/login, guaranteeing smooth authentication.

6. Instructions for Running Locally

How to Run the Platform on Windows:
  1. Compile the C backend:
    gcc -std=c99 -Wall -Wextra -O2 -Ibackend/include backend/src/main.c backend/src/server.c backend/src/algorithm_api.c backend/src/database.o backend/src/sqlite3.o backend/src/cJSON.o backend/src/sha256.o backend/src/algorithms/*.c -o backend/server.exe -lws2_32
  2. Start the server binary:
    .\backend\server.exe 8080
  3. Open your browser to http://localhost:8080.
  4. Navigate to http://localhost:8080/admin to complete your initial first-time administrator setup with your own secure password.
  5. In the Admin dashboard, use the Database Backups panel to take instant online backups or download existing snapshots.
