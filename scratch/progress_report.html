1. Executive Summary: Email-Based Admin Authentication

BrishtiLibrary (বৃষ্টি লাইব্রেরি) administrator authentication has been updated to strictly require a valid email address and password on both first-time setup and subsequent sign-ins.

All credential verification occurs securely on the C backend: email addresses are validated for standard syntax, matched case-insensitively using parameterized SQLite queries (lower(email) = lower(?)), and passwords are authenticated via 5,000-round salted SHA-256 with constant-time hash comparison (constant_time_str_equals).

3. Security Analysis & Limitations

  • Password Hashing Algorithm: Passwords are protected using a 32-character pseudo-random salt and 5,000 iterative rounds of SHA-256 (FIPS 180-2 compliant). Verification uses constant-time string comparison (constant_time_str_equals) to prevent timing side-channel attacks.
  • Documented Security Limitation: SHA-256 is compute-bound rather than memory-hard (unlike Argon2id or bcrypt). For an academic full-stack project in pure C99 without third-party cryptographic libraries, 5,000-round salted SHA-256 provides strong self-contained security while maintaining zero external dependencies and backward compatibility with existing accounts.
  • Credential Hygiene: Admin password hashes and salts are never returned in JSON API responses. Passwords are never stored in browser localStorage or sessionStorage. Sessions are managed exclusively via HTTP-only, SameSite=Lax cookies (bl_session).
