1. Executive Summary & Technology Overview

BrishtiLibrary (বৃষ্টি লাইব্রেরি) is an academic e-commerce bookstore and stationery shop developed for the CSE214 Algorithm Lab. The core academic requirement dictates that the entire backend server must be implemented purely in C (C99), utilizing SQLite via its official C API (sqlite3.h), native Windows Sockets (winsock2.h), and cJSON, with a modern HTML5/CSS3/Vanilla JavaScript frontend.

All backend logic—including session token generation, atomic checkout transactions, stock decrementing, image payload binary signature validation, 5,000-round salted password stretching (FIPS 180-2 SHA-256), and algorithm visualizer microsecond benchmarks—is implemented entirely in C.

3. Existing Issues Diagnosed & Solutions Applied

  • Issue 1: Missing Image Persistence in SQLite Products Table:
    Root Cause: While the upload endpoint saved binary files to frontend/uploads/, the SQL query in db_admin_create_product_json and db_admin_update_product_json omitted the image_url column from the INSERT and UPDATE statements.
    Solution: Added image_url parameter extraction from JSON payloads, updated the parameterized SQL queries in database.c, bound the text buffers, and included image_url in db_admin_get_all_products_json and db_get_products_json.
  • Issue 2: Admin Setup JSON Field Discrepancy:
    Root Cause: The backend endpoint in server.c strictly queried for "email" in the request JSON, while the admin UI and testing scripts submitted "username".
    Solution: Updated server.c to flexibly accept either "username" or "email" across /api/admin/setup and /api/admin/login, guaranteeing smooth authentication.
  • Issue 3: Setup Status JSON Response Format:
    Root Cause: GET /api/admin/setup-status returned {"setup_completed": false} without an explicit "status": "success" property.
    Solution: Added cJSON_AddStringToObject(st, "status", "success") to align with standard API conventions.
  • Issue 4: PowerShell 5.1 Web Request Stalls:
    Root Cause: On Windows PowerShell 5.1, Invoke-WebRequest defaults to invoking the Internet Explorer MSHTML engine if -UseBasicParsing is omitted.
    Solution: Standardized on -UseBasicParsing and Invoke-RestMethod across all automated test scripts.

6. Instructions for Running Locally

How to Run the Platform on Windows:
  1. Compile the C backend:
    gcc -std=c99 -Wall -Wextra -O2 -Ibackend/include backend/src/main.c backend/src/server.c backend/src/algorithm_api.c backend/src/database.o backend/src/sqlite3.o backend/src/cJSON.o backend/src/sha256.o backend/src/algorithms/*.c -o backend/server.exe -lws2_32
  2. Start the server binary:
    .\backend\server.exe 8080
  3. Open your browser to http://localhost:8080.
  4. Navigate to http://localhost:8080/admin to complete your initial first-time administrator setup with your own secure password.
